## Latest confirmed and synchronized audit results

### P0-039 — PARTIAL: unresolved local-download outcome retention
A prior capacity hypothesis was rejected. A real defect was proved: `reconcilePendingLocalDownloads()` can delete a `pendingDownloads` checkpoint after 24 h when Chrome no longer returns the DownloadItem. Clearing Chrome download history does not prove the physical file does not exist, so absence of DownloadItem is not proof that the side effect failed. Unknown outcome must not be irreversibly TTL-dropped; retain bounded dead-letter/manual-resolution/reconciliation evidence. Final sync commit: `59fe8fe89ba3af39dd2202639f25b7bcc48879f0`.

### P1-178 — auth/config generation fence expanded
Storage settlement queues do not protect an OAuth attempt still in network I/O. Scenario: PKCE attempt A (`clientId=A`) starts; newer settings/import commit `clientId=B`; old exchange A returns later and `finishYandexOAuth()` can call `updateYandexConfig(clientId=A)` and roll back B. Auth attempt generation must fence late auth/config commits relative to newer settings/config generations. Final sync commit: `a6829b7c93e8372e69a6531d4f48a486a01b7464`.

### P1-194 — OPEN: IndexedDB eviction / durability class
New finding assigned in this chat. Journal/recovery checkpoints are in extension-origin web-platform storage. `navigator.storage.persist()` is optional/user-triggered and `unlimitedStorage` is not requested; nevertheless code can report `recoveryGuaranteed=true` merely because an IndexedDB checkpoint committed. If storage is not protected from eviction, storage pressure can remove the Journal/checkpoint that is the only local recovery evidence after a physical save side effect. Add an explicit durability-class contract: prove required protection or downgrade the guarantee and UX. Do not automatically prescribe `unlimitedStorage`; it is a product/permission decision. Final source HEAD: `66fd5f828639a9d29f85013fedd4185cd4168e09`.
