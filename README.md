# WebClip PDF Prototype 0.9.8

## Изменения 0.9.8

- При удалении записи режима «Яндекс Диск» пользователь обязан выбрать: оставить PDF на Диске либо переместить его в `<root>/Trash/MM-YYYY`.
- Удалённая операция выполняется раньше удаления local journal entry; при ошибке запись журнала сохраняется.
- Для новых Yandex-записей сохраняются `accountUid`, `rootPath`, `resourceId`, `publicUrl`, `remotePath`; после manual rename/move identity проверяется fail-closed, а один path не считается доказательством при известном `resourceId`.
- Локально скачанные PDF не удаляются при удалении journal entry.

## WIP 0.9.9 — сохранение контекста при переключении видов журнала

`Весь журнал` остаётся глобальным и не фильтруется по исходной странице. Но если он открыт с обычной HTTP(S)-вкладки, WebClip сохраняет исходный `sourceTabId/sourceUrl` в `chrome.storage.session` через `contextId`. Это позволяет в уже открытом `journal.html` переключаться между `Текущий URL`, `Текущий сайт` и `Весь журнал` без потери исходной web-страницы. Popup, открытый поверх вкладки журнала, также восстанавливает этот контекст. Контекст фильтра и вкладка-якорь для открытия справа разделены.

### Audit WIP — P1-003

Перед `Page.printToPDF` выбранный контент теперь проходит bounded resource preparation: common lazy image attributes временно активируются с rollback после print, CSS backgrounds прогреваются renderer-side, используемые fonts — через `Document.fonts`. Общий budget: 15 секунд, до 500 resource tasks, concurrency 8 и bounded DOM scan. P1-003 не использует extension-level `fetch()` и не читает response bytes. Bounded `resourceReport` с redacted resource labels сохраняется в Journal/import-export, PDF header и OperationLog; отдельная ошибка ресурса не блокирует формирование PDF. Chromium regression подтверждает success/failure/redaction/rollback. Manifest остаётся `0.9.8`; это не release QA.

### Audit WIP — P1-001 / P0-003 regression

Новые selection snapshots используют **v3**: помимо structural path сохраняется bounded contextual fingerprint (role/href, parent/neighbor text и sibling indices). При восстановлении `cssPath/domPath` больше не выбирают узел автоматически: кандидаты сравниваются по score, результат получает high/medium confidence, а близкие конкуренты считаются ambiguity и не применяются. Старые v1/v2 snapshots сохраняют legacy restore. Journal показывает confidence/ambiguity/missing diagnostics.

Во время Chromium regression для P1-001 воспроизведён и исправлен regression уже закрытого P0-003: элементы same-origin iframe принадлежат другому JS realm, поэтому `instanceof Element` верхнего окна мог отбрасывать ручной click/auto-content candidates. Selection engine использует realm-neutral `nodeType === 1`; browser-test подтверждает ручной выбор области «Включены» внутри iframe, v3 `framePath` и restore после DOM insertion. Manifest остаётся `0.9.8`; это не release QA.

### Audit WIP — P1-146

Автоматическое локальное скачивание PDF больше не трактует локальный timeout `chrome.downloads.download()` как отмену Chrome side effect. Durable download-intent и Blob URL удерживаются до фактического settlement; late success привязывает исходный `downloadId`, late reject выполняет cleanup. UI отдельно сообщает состояние, когда Chrome ещё подтверждает запуск загрузки. Manifest остаётся `0.9.8` до release QA.

## Изменения 0.9.7

- Контекст исходной вкладки теперь передаётся через `chrome.storage.session` по одноразовому `contextId`; URL и tabId исходного сайта больше не включаются в URL `journal.html`.
- Открытие журнала всегда выполняет service worker, а не action popup. Это исключает зависимость создания extension-вкладки от origin активной страницы.
- Для чтения журнала используется двойная проверка: прямое IndexedDB-чтение и независимая выборка service worker; интерфейс берёт более полную выборку и логирует расхождение в консоль.

- Режим «Весь журнал» полностью отвязан от активной веб-вкладки: открывается service worker-ом без `sourceTabId` и `sourceUrl`.
- `journal.html?mode=all` не запрашивает и не разрешает контекст исходной вкладки; в интерфейсе явно показывается, что URL не используется.
- Открытие полного журнала из popup и контекстного меню централизовано через `WEBCLIP_OPEN_JOURNAL_PAGE`.
- Контекст исходной вкладки сохраняется только для режимов «Текущий URL» и «Текущий сайт».
- Добавлен регрессионный сценарий: полный журнал должен показывать одинаковое число записей при запуске с `chrome://newtab/` и с любой `https://` страницы.


Тестовое Chrome-расширение Manifest V3 для сохранения выбранного содержимого текущей страницы в PDF.

## Установка

1. Распакуйте архив в отдельную папку.
2. Откройте `chrome://extensions`.
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное расширение**.
5. Выберите распакованную папку текущей версии расширения.
6. Если была установлена предыдущая версия, замените её этой версией или нажмите **Обновить** после замены файлов.

## Отображение версии

В основном popup и на странице настроек отображается строка **«Версия расширения: X.Y.Z»**. Номер берётся автоматически из `manifest.json` через `chrome.runtime.getManifest().version`, поэтому при следующих обновлениях его не нужно дублировать вручную в интерфейсе.

## Изменения 0.9.3

### Индикатор сохранения текущего URL на панели Chrome

Для точного URL страницы (fragment `#...` не учитывается) WebClip теперь подсвечивает иконку расширения:

- зелёная — последнее успешное сохранение было не более 24 часов назад;
- оранжевая — последнее успешное сохранение было более 24 часов назад, но не более 30 дней;
- красная — последнее успешное сохранение было более 30 дней назад;
- нейтральная серая — успешных сохранений этого URL в журнале ещё нет.

Исторически в 0.9.3 badge считал уникальные дни любых успешных сохранений. **Начиная с 0.9.4 это правило заменено:** badge и цвет учитывают только полностью успешные выгрузки на Яндекс Диск; локальные скачивания остаются только в журнале.

### Быстрый запуск из контекстного меню

Перед раскрывающимся меню `WebClipper` добавлена самостоятельная верхнеуровневая команда **«Начать выделение WebClipper»**. Она запускает то же состояние областей «Включены/Исключены», что и команда внутри основного меню.

### Иерархический фильтр доменов

В режиме **«Весь журнал»** добавлен иерархический фильтр:

`Все позиции → домен второго уровня → домен третьего уровня`.

Доменные группы сортируются по последней активности, а сами записи внутри любой выбранной группы остаются отсортированными от новых к старым.

### Импорт резервной копии по месяцам

Импорт с Яндекс Диска открывается на текущем месяце `MM-YYYY` и показывает только файлы из соответствующей папки `Backup/Journal/MM-YYYY`. Кнопки **«Предыдущий месяц»** и **«Следующий месяц»** перелистывают месяцы и заново загружают список только выбранного месяца. Переход в будущие месяцы заблокирован.

### Постоянные ссылки на PDF в Яндекс Диске

После успешной загрузки PDF WebClip может опубликовать ресурс через API Яндекс Диска и сохранить его `public_url` в записи журнала. В журнале появляется ссылка **«Открыть сохранённый файл на Яндекс Диске»**. Она не строится из текущего пути или имени файла, поэтому журнал использует ссылку ресурса, а не путь, который может устареть после переименования/перемещения.

Настройка **«Создавать постоянную ссылку Яндекс Диска…»** включена по умолчанию. Важно: опубликованный ресурс доступен любому, у кого есть ссылка, пока публикация не будет снята в Яндекс Диске.

### Прогресс отправки страницы на Яндекс Диск

Во время обычного сохранения страницы на Яндекс Диск WebClip показывает блокирующее окно с этапами:

1. подготовка выбранных областей, ссылок и раскрываемых блоков;
2. формирование PDF Chromium;
3. запись PDF во временный retry-кэш;
4. проверка доступа к Яндекс Диску;
5. подготовка папки сайта;
6. получение upload URL;
7. передача PDF;
8. создание постоянной ссылки;
9. проверка файла и метаданных.

Пока операция выполняется, действия WebClip, которые могли бы изменить selection state, блокируются, а `beforeunload` включает предупреждение при попытке закрыть/перезагрузить страницу. UI скрывается только на короткий момент непосредственного `Page.printToPDF`, чтобы служебное окно не попало в PDF, и сразу возвращается для сетевых этапов.


## Журнал операций

Версия 0.7.0 добавила локальный журнал успешных сохранений. Через основную иконку расширения доступны **Журнал текущего URL**, **Журнал текущего сайта** и **Весь журнал**. Во время режима выделения в верхней панели доступны кнопки **Журнал URL** и **Журнал сайта**.

**P1-009 = REGRESSION.** В Journal добавлен универсальный фильтр: до 8 строк условий, для каждой выбираются `Наименование` (включено по умолчанию), `Комментарии`, `Сайт`, `URL`; строки объединяются `И` либо `ИЛИ`. Фильтр применяется внутри bounded IndexedDB cursor scan до counters/grouping/pagination, поэтому совпадения за первой страницей не теряются. Direct journal read и service-worker fallback используют общий `journal-text-filter.js`.

**P1-025 = REGRESSION.** Для Yandex-записей badge `Яндекс Диск` стал единственной точкой открытия сохранённого PDF; прежняя отдельная ссылка удалена. Badge активен только при валидном Yandex HTTPS `publicUrl`, но сам URL из Journal UI напрямую не открывается: отправляется только `journalEntryId`, а service worker повторно читает запись и применяет security validation P0-037. При отсутствии/невалидности ссылки badge disabled с подсказкой. Локальный destination badge не является действием.

Для каждой успешной операции журнал хранит:

- дату и время успешного действия;
- URL и название страницы;
- имя сформированного PDF;
- способ сохранения: локальное скачивание или Яндекс Диск;
- путь на Яндекс Диске, если использовалась отправка;
- количество областей «Включены» и «Исключены»;
- локаторы DOM-элементов, составлявших области «Включены» и «Исключены».

PDF-файлы в журнале не дублируются. Журнал хранит только метаданные и «рецепт выделения».

### Повторное использование выделения

Для текущего URL можно открыть предыдущую запись и нажать **Применить выделение**. Новые записи сохраняют `SelectionSnapshot v3`: structural locator проверяется по contextual fingerprint. Успешные совпадения помечаются high/medium confidence; если два кандидата слишком близки, WebClip fail-closed не выбирает ни один и показывает ambiguity. Не найденные/неоднозначные области явно показываются пользователю, после чего выделение можно поправить вручную. Старые v1/v2 записи продолжают применяться через legacy restore.

При повторном использовании из журнала **старое имя файла не используется**. При новом сохранении всегда вызывается обычное формирование имени с новой локальной датой и временем.

Для сопоставления записей текущего URL fragment после `#` не учитывается; остальная часть URL, включая query string, учитывается.


### Повторное применение выделения на других URL того же сайта

Начиная с 0.7.2 журнал умеет фильтровать операции не только по точному URL, но и по сайту, нормализованному до третьего уровня домена. Например, шаблон областей «Включены/Исключены», сохранённый на одной странице `its.1c.ru`, можно применить к другой странице `its.1c.ru`. Для URL с более глубокими поддоменами используется тот же нормализатор домена, что и для имени файла/структуры хранения.

При применении шаблона с другого URL расширение использует сохранённые DOM-локаторы и обязательно показывает предупреждение о необходимости проверить восстановленные области. Имя нового PDF всегда формируется заново с текущими датой и временем.

### Где физически хранится журнал

Chrome Extension не может надёжно записывать рабочие данные непосредственно в каталог установленного/распакованного расширения. Поэтому журнал хранится в отдельной IndexedDB расширения `WebClipJournal`. При обновлении файлов той же установленной копии расширения журнал сохраняется. Если загрузить расширение заново как другую копию/из другого каталога и Chrome присвоит другой extension ID, это будет отдельное хранилище.

## Модель областей

Расширение хранит две независимые структуры:

- **Включены** — DOM-области, которые должны попасть в PDF;
- **Исключены** — вложенные DOM-области, которые вырезаются из областей «Включены».

Итоговое правило: **весь DOM внутри областей «Включены» минус поддеревья «Исключены»**.

### Добавление

В режиме **Добавить** клик выбирает DOM-элемент целиком со всеми его дочерними элементами.

- несколько независимых областей «Включены» могут быть смежными;
- независимые области не должны визуально пересекаться;
- если новая область является родителем ранее выбранных областей «Включены», она штатно заменяет их собой;
- существующие области «Исключены» внутри такого нового родителя сохраняются;
- выбирать повторно дочерний элемент уже выбранной области «Включены» не требуется — он уже входит в результат.

### Исключение

Переключитесь в режим **Исключить** и кликните по вложенному DOM-блоку внутри области «Включены».

- исключается весь выбранный блок со всеми потомками;
- нельзя исключить всю область «Включены» целиком;
- более крупное исключение заменяет уже существующие вложенные исключения;
- повторный клик по точно исключённому элементу отменяет исключение.

### Основной контент

Кнопка **Основной контент** пытается автоматически определить типовую область содержимого страницы. Сначала учитывается семантическая разметка (`article`, `main`, `role=main`, `articleBody`), затем используется эвристика по объёму текста, параграфам, заголовкам, изображениям, плотности ссылок и типовым именам `id/class`.

Автоматически найденная область является обычной областью «Включены»:  после этого можно добавить другие области или вручную исключить из неё любые вложенные блоки. **«Основной контент» никогда не создаёт области «Исключены» автоматически и не удаляет предполагаемую рекламу.**

### Подсказки рекламных блоков

Кнопка **Найти рекламу** только подсвечивает вероятные рекламные/промо-блоки внутри выбранных областей «Включены». Она **не исключает их автоматически**. Решение всегда принимает пользователь в режиме **Исключить**.

## Раскрытие спойлеров

Перед формированием PDF расширение пытается раскрыть спойлеры и сворачиваемые блоки **только внутри сохраняемых областей «Включены»**. Поддерживаются нативные `<details>`, элементы с `aria-expanded` / `aria-controls`, Bootstrap-подобные `collapse`/`accordion` и распространённые классы spoiler-разметки.

После формирования PDF раскрытые блоки **не сворачиваются обратно**. Служебные изменения WebClip для печати при этом удаляются.

## PDF

После **Готово** доступны два способа:

1. **Скачать PDF** — стандартное скачивание Chrome;
2. **Отправить на Яндекс Диск** — загрузка PDF напрямую через REST API Яндекс Диска.

В начало PDF добавляется:

1. адрес сайта;
2. полный URL страницы — кликабельный;
3. Название страницы;
4. локальная дата и время формирования копии.

В PDF сохраняются все отображаемые DOM-элементы областей «Включены», кроме явных областей «Исключены». Перед `Page.printToPDF` используется `screen` media, чтобы `@media print` исходного сайта не скрывал выбранный пользователем контент.

Обычные `<a href>` и `<area href>` внутри сохраняемого контента преобразуются во временные абсолютные URL и остаются кликабельными в PDF. Изображения, уже являющиеся частью ссылки, сохраняют исходную ссылку. Обычные `<img>` без ссылки временно оборачиваются ссылкой на исходный `currentSrc/src`, поэтому в PDF по изображению можно открыть оригинал.

## Имя PDF

Для локального **Скачать PDF** и для **Отправить на Яндекс Диск** используется единое правило:

`Название страницы (Title) + имя сайта до третьего уровня домена + локальная дата/время + .pdf`

Полная длина имени файла **вместе с расширением `.pdf` не превышает 100 символов**. При необходимости обрезается `Title`; домен до третьего уровня и дата/время сохраняются полностью в обычном случае. В основной части имени точки и запрещённые символы заменяются; единственная создаваемая расширением точка находится перед `pdf`.

## Настройка Яндекс Диска

Откройте popup расширения → **Настройки Яндекс Диска**.

### OAuth через Client ID

Для полноценного режима зарегистрируйте приложение в Яндекс OAuth и добавьте права:

- `cloud_api:disk.read`;
- `cloud_api:disk.write`;
- `cloud_api:disk.info`.

Для приложения типа **«Для доступа к API или отладки»** Яндекс использует фиксированный Redirect URI `https://oauth.yandex.ru/verification_code`; менять его не требуется. Укажите Client ID в настройках WebClip и выполните двухшаговое подключение через Authorization Code + PKCE. Client Secret в расширение не помещается.

В popup и на странице настроек есть отдельная кнопка **«Инструкция по авторизации»**. Она открывает встроенное руководство: создание OAuth-приложения, права Диска, получение Client ID, ввод одноразового кода, выбор корневой папки и разбор типовых ошибок. Основной текст инструкции доступен офлайн.

Для быстрого локального теста в настройках есть альтернативный режим с готовым OAuth-токеном.

### Корневая папка

В настройках необходимо выбрать отдельную корневую папку, например:

`/WebClips`

Папку можно выбрать из дерева Яндекс Диска, создать из интерфейса настроек либо указать путь вручную. При загрузке отсутствующие каталоги создаются автоматически.

### Служебная структура в корневой папке

Пользователь выбирает только одну корневую папку, например `/WebClips`. WebClipper сам проверяет и при необходимости создаёт:

- `/WebClips/Upload/` — PDF-копии страниц;
- `/WebClips/Backup/Journal/MM-YYYY/` — версионные резервные копии полного локального журнала по месяцам.

Внутри `Upload` файлы распределяются по имени сайта до третьего уровня домена.

Примеры:

- `example.com` → `/WebClips/Upload/example.com/`;
- `its.1c.ru` → `/WebClips/Upload/1c.ru/its/`;
- `support.example.com` → `/WebClips/Upload/example.com/support/`;
- `sub.docs.example.com` → `/WebClips/Upload/example.com/docs/` — уровни выше третьего не добавляются.

Для ряда распространённых составных публичных зон вроде `co.uk` предусмотрена отдельная практическая обработка.

### Отправка

При выборе **Отправить на Яндекс Диск** расширение:

1. проверяет подключение и наличие корневой папки;
2. формирует PDF тем же способом, что и для локального скачивания;
3. создаёт при необходимости дерево папок;
4. получает через `GET /v1/disk/resources/upload` URL загрузки;
5. передаёт PDF методом `PUT` на возвращённый Яндексом URL;
6. показывает окно успеха с полным путём к сохранённому файлу.

Файл не перезаписывается автоматически (`overwrite=false`). Благодаря дате и времени до секунд совпадение имён маловероятно; при конфликте Яндекс Диск вернёт ошибку.

## Поведение при ошибке Яндекс Диска

PDF для отправки формируется **один раз**. Сразу после формирования расширение сохраняет его во временном локальном IndexedDB-кэше, привязанном к текущей вкладке. Если передача на Яндекс Диск завершилась ошибкой, кэш не удаляется.

Кнопка **Повторить отправку** повторяет только сетевую загрузку **того же PDF и с тем же именем файла**. `Page.printToPDF` повторно не вызывается, DOM страницы повторно не подготавливается. Это правило сохраняется и если service worker Manifest V3 успел выгрузиться между попытками: кэш хранится в IndexedDB расширения, а не только в памяти процесса.

Из окна ошибки можно также нажать **Скачать этот PDF** — локально скачивается тот же уже сформированный файл без повторного формирования.


При любой ошибке отправки окно результата намеренно оформляется как состояние, требующее вмешательства пользователя: красная контрастная рамка и фон, предупреждающий значок, метка **«Требуется действие»**, заголовок ошибки и отдельный текст причины. Успешная отправка использует спокойное зелёное состояние **«Операция выполнена»**.

При ошибке:

- области «Включены» не очищаются;
- области «Исключены» не очищаются;
- пользователь видит текст ошибки и явное указание разобрать причину;
- можно открыть настройки Яндекс Диска;
- можно повторить отправку;
- можно вместо этого выбрать **Скачать этот PDF** — будет использован тот же кэшированный файл;
- можно вернуться к выделению и изменить области.

Очистка выделений выполняется только после успешного результата и нажатия **Закрыть**, либо при явной отмене пользователем.

## Offline

Локальное формирование и скачивание PDF не требует собственного сервера и может работать с уже загруженным содержимым страницы без интернета. Отправка на Яндекс Диск, разумеется, требует сетевого соединения.

## Технические замечания прототипа

- PDF создаётся локально Chromium через `Page.printToPDF`;
- на время формирования Chrome может показывать индикатор подключения отладчика;
- Яндекс REST API вызывается непосредственно из service worker расширения;
- OAuth access token хранится только в `chrome.storage.session` и не сохраняется постоянно; legacy-токен старой сборки при первом использовании переносится из `storage.local` в session и persistent-копия удаляется; после перезапуска/обновления расширения требуется повторное подключение Яндекс Диска;
- iframe, canvas, видео, Shadow DOM и нестандартные JavaScript-виджеты печатаются настолько, насколько Chromium умеет представить их в статическом PDF;
- ресурсы, которые к моменту печати не загружены и недоступны по сети, могут отсутствовать в PDF.


## OAuth через фиксированный Redirect URI (0.6.0)

Для приложения Яндекс OAuth используется фиксированный адрес:

`https://oauth.yandex.ru/verification_code`

Схема подключения:

1. В настройках расширения указать Client ID.
2. Нажать «1. Получить код». Расширение генерирует PKCE `code_verifier`/`code_challenge`, сохраняет verifier только на время текущей сессии и открывает Яндекс OAuth.
3. Разрешить доступ. Яндекс покажет одноразовый код на странице `verification_code`.
4. Скопировать код, вернуться в настройки и нажать «2. Завершить подключение».
5. Расширение обменивает код на OAuth access token, передавая `code_verifier`. Client Secret не хранится и не используется.

Если access token истёк, расширение просит пройти PKCE-подключение заново. Автоматическое обновление через refresh token намеренно не используется, поскольку для такого запроса Яндекс документирует Client Secret, который нельзя безопасно встраивать в Chrome Extension.

## Имя PDF

Для локального скачивания и Яндекс Диска имя формируется одинаково в порядке:

`Название страницы (Title)__Имя сайта до третьего уровня домена__YYYY-MM-DD_HH-MM-SS.pdf`

Максимальная длина полного имени, включая `.pdf`, — **100 символов**. Если исходный Title длинный, расширение рассчитывает доступный бюджет после домена, даты/времени, разделителей и расширения и обрезает только Title до нужной длины.

Пример для `https://its.1c.ru/...`:

`Регистры накопления в 1С__its_1c_ru__2026-08-23_17-00-00.pdf`

Если hostname содержит более трёх уровней, для обычных доменных зон используются последние три уровня. Например, `sub.docs.example.com` -> `docs_example_com`. Для распространённых составных публичных зон (например, `co.uk`) учитывается базовый домен и один уровень перед ним.

Все недопустимые символы заменяются безопасными символами. Точки внутри Title и имени сайта также заменяются на `_`, поэтому единственная точка в итоговом имени отделяет расширение `.pdf`.

## Frame-aware страницы

Начиная с 0.8.0 WebClipper анализирует same-origin `iframe/frame` как отдельные DOM-контексты. Это позволяет выбирать основной контент, вручную добавлять области «Включены/Исключены» и восстанавливать шаблоны внутри встроенных документов, например на страницах 1С:ИТС, где статья фактически находится внутри iframe. ## Экспорт, импорт и резервирование журнала

В версии 0.9.1 исправлено чтение полного журнала для экспорта/резервной копии: IndexedDB-индекс `createdAt` обходится стандартным курсором `next` (по возрастанию). Это устраняет ошибку `The provided value 'asc' is not a valid enum value of type IDBCursorDirection`.

В версии 0.9.2 резервные копии на Яндекс Диске стали **версионными**. Каждая успешная ручная или фоновая выгрузка создаёт новый JSON-файл и не удаляет/не перезаписывает предыдущие. Структура: `<root>/Backup/Journal/MM-YYYY/WebClip_Journal_YYYY-MM-DD_HH-MM-SS-SSS.json`, где `MM-YYYY` формируется по локальной дате компьютера.

Журнал является локальным источником истины и хранится в IndexedDB. Полный журнал можно выгрузить одним JSON-файлом и восстановить из него. Импорт полностью заменяет локальный журнал и требует ручного ввода показанного 9-значного случайного кода. При импорте с Яндекс Диска WebClip сначала показывает отдельное окно со списком конкретных резервных файлов; пользователь обязан явно выбрать версию, автоматического выбора «последней» копии нет.

При ручной выгрузке на Яндекс Диск на странице Журнала и в Настройках показывается модальное окно прогресса с этапами: чтение журнала, формирование JSON, проверка Яндекс Диска, подготовка `MM-YYYY`, получение upload URL, передача файла и проверка результата. Пока операция идёт, закрытие вкладки защищено `beforeunload`; окно прогресса нельзя закрыть. После успеха или ошибки окно переходит в отдельное финальное состояние и его можно закрыть вручную.

Фоновая резервная копия может быть включена в настройках. По умолчанию период — 1440 минут (24 часа), отдельно задаётся интервал повтора после ошибки. Если Chrome пропустил очередной срок, service worker проверяет просрочку при следующем запуске/возобновлении и выполняет операцию при первой возможности. В popup показываются время последней успешной и последней неудачной фоновой попытки.

## Удаление записи журнала и файл Яндекс Диска (0.9.8)

Для записи режима `Яндекс Диск` команда **«Удалить запись»** больше не удаляет журнал немедленно. Пользователь обязан выбрать один из двух взаимоисключающих вариантов:

1. **Оставить файл на Яндекс Диске** — удаляется только локальная запись журнала.
2. **Так же удалить файл на Яндекс Диске** — файл сначала переносится в `<root>/Trash/MM-YYYY`, где `MM-YYYY` формируется по локальной дате удаления, и только после подтверждённого перемещения удаляется запись журнала.

`Trash` — обычная служебная папка внутри выбранного WebClip root, а не системная Корзина Яндекс Диска. Поэтому операция является обратимой вручную: файл можно найти и перенести обратно.

Если удалённое действие завершилось ошибкой или WebClip не смог однозначно найти файл, локальная запись журнала сохраняется. P1-090 фиксирует account/root identity: новые записи сохраняют `accountUid` и `rootPath`; mismatch с текущим аккаунтом/root останавливает destructive action. При известном `resourceId` сохранённый path сам по себе недостаточен; exact `publicUrl` допускается как secondary identity только при отсутствующем `resource_id`, но не при конфликтующем ID. Legacy entries сохраняют managed-path fallback.
