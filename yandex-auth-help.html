WebClip PDF Prototype

Авторизация в Яндекс Диске

Пошаговая настройка OAuth для отправки PDF из WebClip напрямую на ваш Яндекс Диск.

Открыть настройки WebClip
Используемая схема: Authorization Code + PKCE с фиксированным Redirect URI https://oauth.yandex.ru/verification_code. Client Secret расширению не нужен.
Содержание 1. Создать приложение Яндекс OAuth 2. Выдать права Яндекс Диска 3. Скопировать Client ID 4. Получить код подтверждения 5. Завершить подключение 6. Выбрать корневую папку 7. Проверить работу Типовые ошибки
1

Создайте приложение в Яндекс OAuth

  1. Войдите в тот аккаунт Яндекса, на Диск которого должны сохраняться PDF.
  2. Откройте страницу создания OAuth-приложения.
  3. Выберите тип «Для доступа к API или отладки».
  4. Укажите понятное название, например WebClip PDF, и актуальную контактную почту.
  5. Для такого типа приложения Redirect URI задаётся Яндексом автоматически. Он должен быть https://oauth.yandex.ru/verification_code. Менять его не требуется и нельзя.

Открыть создание приложения Яндекс OAuth

2

Разрешите приложению работу с Яндекс Диском

В разделе доступа к данным добавьте права Яндекс Диска, необходимые текущей версии WebClip:

cloud_api:disk.read чтение дерева папок и проверка существующих ресурсов; cloud_api:disk.write создание папок и загрузка PDF; cloud_api:disk.info получение информации о Диске и проверка подключения.

Важно: если изменить права приложения уже после получения кода, старый код может перестать подходить. В таком случае начните авторизацию заново.

3

Скопируйте Client ID

  1. Сохраните приложение Яндекс OAuth.
  2. Откройте его карточку.
  3. Скопируйте значение ClientID / Client ID.
  4. В WebClip откройте Настройки Яндекс Диска и вставьте Client ID в одноимённое поле.

Не вставляйте Client Secret в расширение. Текущая схема WebClip его не использует.

4

Получите одноразовый код подтверждения

  1. В настройках WebClip нажмите «1. Получить код».
  2. Расширение локально создаст случайный code_verifier и производный code_challenge для PKCE.
  3. Откроется страница Яндекс OAuth. Проверьте аккаунт и подтвердите запрашиваемый доступ.
  4. Яндекс перенаправит браузер на фиксированную страницу https://oauth.yandex.ru/verification_code.
  5. На этой странице Яндекс покажет код подтверждения. Скопируйте его.

Код действует 10 минут. Если время истекло, снова нажмите «1. Получить код» и используйте новый код.

5

Завершите подключение в WebClip

  1. Вернитесь во вкладку настроек WebClip.
  2. Вставьте код Яндекса в поле «Код подтверждения».
  3. Нажмите «2. Завершить подключение».
  4. WebClip отправит код вместе с сохранённым code_verifier на OAuth-сервер Яндекса и получит access token.
  5. При успехе состояние изменится на «Подключено».

PKCE связывает одноразовый код именно с той попыткой авторизации, которую начал WebClip. Поэтому нельзя получить код в одном экземпляре/профиле расширения, а завершить его в другом.

6

Выберите корневую папку Яндекс Диска

  1. В настройках нажмите «Выбрать папку на Диске».
  2. Откройте существующую папку или создайте новую, например /WebClips.
  3. Нажмите «Выбрать эту папку».

Дальше WebClipper сам поддерживает служебные папки Upload и Backup/Journal. Например, PDF с its.1c.ru будет сохраняться в /WebClips/Upload/1c.ru/its/, а версии резервной копии полного журнала — в месячных папках вида /WebClips/Backup/Journal/08-2026/WebClip_Journal_2026-08-23_18-53-10-000.json. Предыдущие версии не удаляются.

7

Проверьте подключение

  1. Нажмите в настройках «Проверить доступ».
  2. Затем откройте обычную веб-страницу, запустите WebClip и выделите область.
  3. Нажмите «Готово» → «Отправить на Яндекс Диск».
  4. После успешной загрузки WebClip покажет полный путь к PDF на Диске.

Если отправка завершена успешно, выбранные области можно очистить. При ошибке WebClip сохраняет области Включены/Исключены, чтобы отправку можно было повторить или выбрать «Скачать PDF».

Типовые ошибки авторизации

bad_verification_code
Код введён неверно. Проверьте его и повторите. Код Яндекса обычно является коротким числовым кодом.
invalid_grant
Код просрочен, уже использован или не соответствует текущей PKCE-сессии. Получите новый код через «1. Получить код».
invalid_client
Неверный Client ID, приложение удалено/заблокировано либо выбран не тот OAuth-клиент.
invalid_scope
Набор прав изменился или запрошенное право недоступно приложению. Проверьте права Яндекс Диска в OAuth-приложении и начните авторизацию заново.
unauthorized_client
OAuth-приложение не может выполнять эту авторизацию, например ожидает модерации или заблокировано.
Кнопка «Завершить» говорит, что нет активной попытки
Сессия расширения была потеряна/перезапущена или прошло слишком много времени. Снова нажмите «1. Получить код».
Авторизация есть, но Диск возвращает 401/403
Токен недействителен либо не хватает прав. Переподключите Яндекс Диск после проверки scopes приложения.

Что WebClip хранит локально

  • Client ID и выбранный путь Яндекс Диска — в локальном хранилище расширения.
  • code_verifier — только во временном session storage на время попытки авторизации.
  • OAuth access token — в chrome.storage.local текущего прототипа.
  • Client Secret — не запрашивается и не хранится.

Для публичного распространения расширения модель долговременного хранения токена стоит дополнительно усилить. Текущая реализация рассчитана прежде всего на тестирование и личное использование прототипа.
