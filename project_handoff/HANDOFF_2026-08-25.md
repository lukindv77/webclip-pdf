### Закрыто этим аудитом

**P1-155 — REGRESSION.** Реальные лимиты DOM locator enumeration. Убрано `[...querySelectorAll(...)].slice(...)`, которое сначала materialize'ило весь NodeList. Top frame и frame-agent используют bounded indexed tag collections; cross-origin iframe enumeration и link-density path также bounded.

**P1-159 — REGRESSION.** Large-result UI optimization:

- OperationLog search debounce 120 ms;
- rendering по 80 строк/frame;
- `DocumentFragment`;
- full raw OperationLog JSON materialize только при явном Show/Copy;
- JSON кэшируется и не stringify'ится повторно без необходимости;
- linked Journal OperationLog имеет lazy/cached JSON;
- Journal domain tree строится detached и монтируется одним этапом.

Permanent OperationLog diagnostics **не урезаны и не удалены**.

### Новые OPEN P0

**P0-063 — global offscreen signed-transfer admission/memory budget.** Сейчас Blob URL имеют budget, но несколько крупных signed-transfer могут одновременно держать 50–64 MiB payload/Blob/fetch body. Нужен global actual-settlement count + byte reservation до materialization и release только после реального settlement.

**P0-064 — flattened iframe deep-clone preflight budget.** P1-151 ограничивает computed-style copy, но `cloneNode(true)` и полные descendant arrays создаются раньше лимита. Нужен bounded node/text/estimated-byte preflight до deep clone и инкрементальный traversal, чтобы pathological iframe fail-safe завершался контролируемой ошибкой вместо OOM.

- **P1-156** — page-owned native Save As listener/release cleanup lifecycle: fallback lifetime + `downloads.search` reconciliation + bounded/dedup release control RPC. Native `saveAs:true` остаётся page-owned и без artificial timeout/retry.

## 5. Non-negotiable architecture/security invariants

- Никогда не переписывать проект с нуля.
- GitHub `main` — source of truth; перед новым изменением fetch fresh current `main`.
- OAuth access token session-only; refresh token не сохранять.
- Legacy persistent OAuth-token cleanup awaited/fail-closed.
- PKCE S256/state сохранять.
- Yandex managed paths канонизировать и identity/account/root/resource проверять fail-closed.
- Non-idempotent Chrome/network side effects: durable checkpoints и actual late-settlement reconciliation; blind retry запрещён.
- Native `chrome.downloads.download({saveAs:true})` остаётся extension-page owned, не переносить в MV3 worker и не ставить artificial dialog timeout.
- Offscreen Blob/PDF lifecycle bounded; temporary resources освобождать с actual-state reconciliation.
- IDB/runtime operations bounded; readonly result публиковать только после transaction completion там, где это архитектурно требуется.
- OperationLog v2 append-only audit semantics сохранять.
- Permanent diagnostics `pageAnalysis`, `printDiagnostics`, frame/root measurements, `page-analysis`, `copy-save` сохранять как product functionality.
- Cross-origin iframe остаётся permission-gated через optional host permissions и sender/frame/document validation.
- Full PSL handling сохранять.
- Incognito privacy boundary сохранять fail-closed.
- Manifest остаётся `0.9.8`; **не** менять на 0.9.9 без реального unmanaged unpacked Chrome + real Yandex release QA и прямого запроса пользователя.
- Не создавать build/Release без прямого запроса пользователя.
- Temporary GitHub Actions patch workflow допустим для огромных файлов, но должен быть удалён в финальном product commit.

## 7. Git/commit workflow

- Изменения группировать по одной смысловой задаче/этапу.
- После закрытия задачи — один meaningful commit или небольшая связанная серия.
- Перед push сверить fresh HEAD, чтобы не затереть чужие изменения.
- При использовании one-shot GitHub Actions workflow:
  - сначала guarded baseline check;
  - применить patch;
  - полный syntax + deterministic gate;
  - только после PASS commit product changes;
  - удалить workflow/patch files в том же финальном commit.
- Старые isolated VM tests могут требовать dependency stub/harness update после централизации helper; сначала доказать, что product runtime корректен, затем чинить test sandbox, не наоборот.
