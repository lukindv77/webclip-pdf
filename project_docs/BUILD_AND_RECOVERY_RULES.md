# Правила новой сборки и recovery

## Обязательное правило

**Ни одна новая версия WebClip после 0.7.1 не должна отдаваться пользователю без обновлённого recovery-архива внутри самой папки расширения.**

Путь:

`project_recovery/WebClip_Project_Recovery_vX.Y.Z.zip`

## Порядок изменения версии

1. Внести изменения в runtime-код.
2. Обновить `manifest.json` → `version`.
3. Обновить `README.md` и соответствующие `project_docs/*`:
   - требования;
   - changelog и причина;
   - architecture, если изменена;
   - P0/P1/P2;
   - ограничения;
   - тест-план при новом поведении.
4. Запустить `project_tools/build_recovery_archive.py`.
5. Проверить содержимое внутреннего recovery zip.
6. Запустить JS syntax check.
7. Упаковать всю папку расширения во внешний ZIP для пользователя.
8. Проверить, что внешний ZIP содержит внутренний recovery ZIP с той же версией.

## Что входит в recovery zip

- `RECOVERY_README.md`;
- `BUILD_METADATA.json`;
- `FILE_HASHES.sha256`;
- `project_docs/`;
- `source/` — snapshot исходников и проектных инструментов, **без самого recovery zip**, чтобы не было рекурсии.

## Почему recovery zip не включает самого себя

Иначе возникла бы бесконечная рекурсия. Внутренний архив содержит полный исходный snapshot, достаточный для воссоздания папки расширения и повторного создания recovery zip скриптом.

## Проверка нового чата

Если новый чат получил только внешний build ZIP:

1. распаковать внешний ZIP;
2. найти `project_recovery/WebClip_Project_Recovery_vX.Y.Z.zip`;
3. распаковать его;
4. сначала прочитать `RECOVERY_README.md` и `project_docs/RESTORE_PROMPT.md`;
5. затем использовать `source/` как source of truth текущей версии.

## Handoff между чатами

Handoff-архивы между чатами не создаются после каждой P-задачи автоматически. Они собираются только по прямому запросу пользователя. Это правило не отменяет versioned recovery archive при фактическом выпуске новой версии.
