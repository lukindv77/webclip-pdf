# Ключевые архитектурные решения и причины

## DOM selection вместо текстового Selection API

WebClip выбирает DOM-блоки, а не только текстовый диапазон. Это нужно для сохранения структуры, изображений, таблиц и ссылок.

## «Включены» + «Исключены» вместо плоского списка областей

Плоская модель ломается, когда пользователь хочет сохранить статью целиком, но вырезать рекламу/навигационный блок внутри. Модель «Включены/Исключены» естественно описывает правило «всё внутри контейнера кроме явно вырезанных поддеревьев».

## Автоматизация не удаляет контент сама

«Основной контент» создаёт область «Включены». «Найти рекламу» только подсвечивает кандидатов. Это снижает риск потери важного содержимого из архивной копии.

## Page.printToPDF вместо screenshot→PDF

Причины:
- текст остаётся текстом;
- hyperlinks могут сохраняться как PDF annotations;
- качество печати лучше для документации;
- меньше размер для текстовых страниц.

Ограничение: финальная статическая печать зависит от возможностей Chromium и состояния DOM.

## Media=screen перед printToPDF

Сайты часто имеют `@media print`, который скрывает блоки. Пользователь требует сохранять выбранный контент, поэтому перед `Page.printToPDF` включается экранный media-mode.

## Временная нормализация ссылок

Относительные `href` могут переводиться в безопасное абсолютное печатное представление. Временная запись принадлежит конкретной print-generation: после печати исходное значение восстанавливается только если host page не изменила тот же атрибут после WebClip. Stale rollback не имеет права перезаписывать более новое состояние страницы (P1-221).

## Изображения как ссылки на оригинал

Если `<img>` не находится внутри `<a>`, печатное представление должно сохранять возможность открыть исходный URL изображения. Реализация не должна полагаться на blind structural rollback: generated wrapper/marker имеет точную print-generation/ownership и удаляется только если всё ещё является объектом, созданным WebClip; более новая host-page структура не заменяется старым snapshot (P1-219).

## Disclosure-контент в печатном представлении

Полезный скрытый контент желательно включать в PDF, но это требование не даёт WebClip права выполнять произвольные page-owned controls. Допустимы inert/static representation и нативное состояние, которое можно безопасно представить без synthetic click/submit/navigation/business logic; если для раскрытия требуется реальное действие приложения, нужен явный пользовательский шаг или безопасная альтернативная репрезентация (P0-067/P1-212).

## Яндекс OAuth: PKCE + verification_code

Для типа приложения с фиксированным Redirect URI нельзя использовать обычный callback расширения. PKCE позволяет не встраивать Client Secret в клиентский extension.

## Не использовать Client Secret в расширении

Любой secret, встроенный в Chrome Extension, можно извлечь из пакета. Поэтому secret не является секретом. Автоматический refresh, требующий Client Secret, не используется.

## PDF retry хранится в IndexedDB

Manifest V3 service worker может быть выгружен. Кэш только в JS memory ненадёжен. IndexedDB сохраняет PDF между выгрузками service worker в рамках установленной копии расширения.

## Журнал хранится в IndexedDB

Папка расширения — не подходящее runtime-хранилище. IndexedDB доступна расширению, переживает перезапуск браузера и обычное обновление той же установленной копии.

## Recovery architecture — Git-first (SUPERSEDED old nested-archive rule)

Старое решение вкладывать полный recovery ZIP внутрь каждой пользовательской сборки отменено P0-019. Текущий WIP source snapshot — exact Git commit SHA; released source state определяется exact release commit + annotated tag. Пользовательский extension ZIP не обязан содержать nested source/recovery ZIP. Отдельный recovery ZIP допускается как offline/disaster artifact только из clean exact commit и содержит metadata + SHA-256 manifest. Текущая authority: `BUILD_AND_RECOVERY_RULES.md`.

## Решение: журнал сайта как источник повторно используемых шаблонов

**Решение:** считать записи одного нормализованного домена до третьего уровня потенциально совместимыми шаблонами областей «Включены/Исключены».

**Почему:** типовые страницы одного сайта часто имеют одинаковую структуру, поэтому это экономит повторную настройку.

**Ограничение:** DOM может отличаться; восстановление не является гарантией корректности и требует пользовательской проверки.

## Same-origin iframe как полноценный selection scope

**Решение:** локатор области состоит из `framePath + element locator`, а события выбора ставятся во все доступные same-origin документы.

**Почему:** на 1С:ИТС и других порталах верхний `body` является оболочкой, а полезный документ находится в iframe. Анализ только top document систематически выбирает неверную область.

## Один rootPath Яндекс Диска и зарезервированные служебные папки

**Решение:** пользователь не выбирает отдельные папки для PDF и backup. WebClipper владеет именами `Upload` и `Backup/Journal` внутри выбранного root.

**Почему:** уменьшается число настроек, исключается рассогласование путей, фоновый backup способен самовосстанавливаться созданием отсутствующих каталогов.

## Журнал остаётся локальным, Yandex backup — только disaster recovery

**Решение:** рабочий CRUD журнала всегда идёт в IndexedDB. На Яндекс Диск добавляются отдельные полные JSON snapshot-версии; удалённые backup-файлы не являются рабочей базой.

**Почему:** сетевой сервис не должен влиять на доступность/скорость локальной истории; один полный файл проще проверять и восстанавливать, чем набор incremental fragments.

## 9-значный ручной код для массово опасных операций

**Решение:** import/clear-domain/clear-all требуют read-and-type code; delete-one использует обычный confirm.

**Почему:** массовая потеря журнала существенно опаснее удаления одной строки. Дополнительная ручная операция снижает вероятность случайного клика, не усложняя повседневный CRUD.

## Background backup — one-shot scheduling относительно последнего success

**Решение:** normal alarm планируется от последнего успешного backup; при старте выполняется overdue-check; failure ставит отдельный retry alarm.

**Почему:** `chrome.alarms` не выполняется при закрытом браузере. One-shot + startup check лучше отражает требование «каждые N минут, а пропущенное выполнить при первой возможности», чем слепой periodic alarm.

## Context menu не содержит второй реализации бизнес-логики

**Решение:** context menu отправляет команды существующему `content.js` или открывает существующие extension pages.

**Почему:** два независимых набора handlers быстро расходятся и создают регрессии. UI entry points должны делить одну state machine.


## Версионный backup журнала и явный выбор при импорте (0.9.2)

**Решение:** резервные копии журнала больше не перезаписывают один файл. Каждая выгрузка создаёт новый полный JSON в `Backup/Journal/MM-YYYY` с локальной датой/временем в имени и `overwrite=false`.

**Причина:** backup должен позволять откатиться к конкретному состоянию, а не только к последнему. Для восстановления пользователь явно выбирает файл; автоматический выбор последней версии запрещён, чтобы снизить риск необратимого replace не той копией.

**UX:** ручной export показывает блокирующее окно прогресса с реальными этапами service worker и `beforeunload`-защитой вкладки до финального успеха/ошибки.


## 0.9.3 — решения

### Индикатор URL вычисляется из Journal
Не создаётся отдельная агрегированная БД состояния иконки. Source of truth остаётся `WebClipJournal`; по точному `urlKey` вычисляются `lastSavedAt` и множество `localDayKey`. Это исключает рассинхронизацию между журналом и badge.

### Для открытия Yandex PDF хранится `public_url`, а не ссылка из пути
Путь/имя файла могут измениться. Поэтому после upload при включённой настройке ресурс публикуется, а journal entry сохраняет `publicUrl`. `remotePath` остаётся диагностическим значением «путь при сохранении».

### Retry page upload после неизвестного/частичного settlement

Историческая стратегия «существующий `remotePath` + совпадающий byte-size = ранее загруженный объект» признана недостаточной и не является current correctness authority. По P1-184 path+size не доказывают object/content identity: retry/recovery должен использовать immutable operation-owned bytes/content fingerprint и точный remote object/proven-transfer receipt. Неизвестный settlement остаётся `unknown` до reconciliation; совпадение пути и размера не разрешает adoption/publication/final success.

### Page progress не должен попадать в PDF

Progress UI остаётся видимым во время подготовки и сетевых этапов. Непосредственно перед `Page.printToPDF` extension-owned progress root может быть временно скрыт и затем восстановлен. Любые временные изменения host DOM/атрибутов/обёрток очищаются только при доказанном ownership текущей print-generation; compare-before-restore не позволяет late cleanup перезаписать новое состояние страницы (P1-218…P1-224).

## Decision: direct IndexedDB read for journal UI (0.9.6)
The standalone journal view reads `WebClipJournal/entries` directly instead of asking the service worker for its display list. Rationale: the persistent database is already the source of truth, and the extra message/filter hop produced a reproducible case where the full journal differed depending on the source browser tab. Mutations remain centralized in the service worker.

## Полный журнал не имеет source-page контекста

`Весь журнал` является глобальным представлением extension-данных и не должен зависеть от активного сайта. Открытие выполняет service worker; сведения об исходной вкладке вынесены в `chrome.storage.session` и используются только как вспомогательный контекст для URL/site режимов. Это решение принято после воспроизводимой ошибки, когда журнал отличался для `chrome://newtab/` и обычной веб-вкладки.
