### 2.2 Current `pdf-print-guard.js` freezes only after render-state hide

6. set script execution enabled again;
7. restore render state visible.

This order is materially stronger than the historical unguarded print path, but it leaves all of `prepareForPrint()` plus the render-state-hide message itself before the page-script freeze barrier.

## 6. Fresh finding B — render-state hide MutationObserver also wins before script-disable

A second observer watches style changes on `#webclip-pdf-extension-root`. When current render-state handling hides the WebClip UI, the observer appends `C35_RENDERSTATE_OBSERVER_MUTATION` inside the selected scope.

The result does not mean UI hiding is itself inherently wrong. It means an operation whose authoritative PDF bytes depend on the same live page cannot perform page-observable pre-freeze mutations and still claim exact admitted-state fidelity by silence.

## 13. External standards / comparable-engine research

External sources are architecture and failure-mode input only; current source plus fresh physical Chrome controls determine the verdict.

### Browser lifecycle semantics

Current MDN documents that `beforeprint` is fired when a document is about to print and can be used to change page content before printing. The direct control reproduces this ordinary platform behavior.

Reference: https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeprint_event

### CDP script execution fence

Current Chrome DevTools Protocol documents `Emulation.setScriptExecutionDisabled` as switching page script execution. The fresh current-guard control proves this fence suppresses the tested `beforeprint` script/microtask when applied before `Page.printToPDF`.

Reference: https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setScriptExecutionDisabled

### snapDOM — non-destructive capture architecture

Recent snapDOM work explicitly includes stopping live-DOM mutation during capture, isolated clone/session state, animation handling and mutation-aware capture/reconciliation. The transferable lesson is representation ownership: preparation should not rely on page-observable live mutation if exact snapshot semantics are required.

Reference: https://github.com/zumerlab/snapdom/blob/main/CHANGELOG.md

## 14. Architecture implications

The fresh C35 result narrows the desired sequencing:

`admitted user state -> page-non-authoritative frozen/static representation -> representation-local preparation -> script/page-authority fence -> physical PDF -> byte settlement`

rather than:

`admitted state -> mutate live page for preparation -> hide UI in live page -> freeze page scripts -> print later live generation`.

A future implementation should:

1. establish exact document/application/selection generation before preparation;
2. freeze/materialize selected content into a WebClip-owned representation before page-observable transformations;
3. perform headers, selected-only filtering, disclosure/static flow and resource materialization in that representation;
4. retain the current P0-071 physical script fence as defense-in-depth for any renderer-side live execution still possible;
5. avoid relying on page `beforeprint/afterprint` delivery for correctness;
6. preserve exact cleanup/rollback for unavoidable pre-freeze live changes;
7. expose truthful degraded/unknown/reconfirm behavior if source generation changes before the immutable representation is committed;
8. stop the authoritative interval at physical byte settlement rather than freezing the host indefinitely.
