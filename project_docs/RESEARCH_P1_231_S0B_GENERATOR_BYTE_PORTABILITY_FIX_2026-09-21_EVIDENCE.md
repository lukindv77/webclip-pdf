# P1-231 S0-B PSL generator byte-portability correction — 2026-09-21

Status: **IMPLEMENTED SOURCE CORRECTION / CROSS-PLATFORM RE-PROOF PENDING**

## Scope

This tranche makes the existing Public Suffix List generator emit exact UTF-8 bytes without platform text-newline translation.

Changed production tooling:

`project_tools/build_public_suffix_js.py`

from:

`Path.write_text(code, encoding='utf-8')`

to:

`Path.write_bytes(code.encode('utf-8'))`

The generated string already contains explicit LF characters. Writing its UTF-8 encoding as bytes removes the operating-system newline translation that the earlier S0-B Windows probe proved could turn those LF bytes into CRLF.

No `public-suffix.js` package bytes are intentionally changed by this tranche. The generator remains outside the canonical extension package.

## Why this correction is required

Python 3.12 documents that text output with `newline=None` translates written `\n` characters to the system default line separator, while binary output performs no text newline translation.

Comparison references:

- Python 3.12 pathlib `Path.write_text` / `Path.write_bytes`:
  https://docs.python.org/3.12/library/pathlib.html
- Python 3.12 text I/O newline semantics:
  https://docs.python.org/3.12/library/functions.html#open
- Git `gitattributes` EOL normalization / working-tree conversion:
  https://git-scm.com/docs/gitattributes

These sources support the correction mechanism only. Current WebClip authority remains the repository contracts and exact project evidence.

## Why Git EOL policy is not the fix

Git may normalize repository text to LF while materializing different working-tree EOLs depending on attributes/config/platform. S0-B therefore continues to compare generated bytes with the exact committed Git blob rather than trusting working-tree presentation.

Adding verifier-side CRLF/LF normalization would weaken package identity and remains forbidden.

## Deterministic model changes

The S0-B source-generation model, the S0-B strict parser/composition refinement, and S0-F candidate-generation verifier now require the exact byte-write form and reject a regression back to the old text-mode write.

Case-count / downstream stdout markers are intentionally preserved. No S1 predecessor semantics are advanced.

S0-F still passes `portabilityReady=false` for the real current candidate. Its synthetic future `portabilityReady=true` path remains only a model of what can be admitted after the physical prerequisite is closed.
