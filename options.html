WebClip — Яндекс Диск

Подключение облачного хранилища, выбор единственной корневой папки и настройка резервного копирования журнала.

1. Подключение

Проверяем состояние…
В приложении Яндекс OAuth должен быть указан фиксированный Redirect URI https://oauth.yandex.ru/verification_code. Для OAuth-приложения нужны права cloud_api:disk.read, cloud_api:disk.write и cloud_api:disk.info. Используется Authorization Code + PKCE, поэтому Client Secret расширению не нужен.
Шаг 1

Откройте Яндекс OAuth, разрешите доступ. На странице verification_code Яндекс покажет код подтверждения.

Шаг 2

Скопируйте показанный Яндексом код и вставьте его сюда. Код действует ограниченное время.

OAuth-токен хранится только в chrome.storage.session и удаляется после полного закрытия Chrome, перезагрузки или обновления расширения. После нового запуска Chrome для операций с Яндекс Диском потребуется повторное подключение. Постоянное хранение OAuth-токена намеренно не используется.
Тестовый вариант: использовать готовый OAuth-токен

Можно вставить отладочный токен с правами чтения, записи и информации о Диске. Это удобно для локального тестирования прототипа.

2. Корневая папка

WebClipper сам создаёт внутри выбранной папки служебные каталоги Upload, ReadmeLater, Trash (по мере необходимости) и Backup/Journal. PDF режима «Прочитано» сохраняются в Upload, режима «Прочитать позже» — в ReadmeLater, версии резервной копии полного журнала — в Backup/Journal/MM-YYYY.

/
Пример для корня /WebClips: обычный PDF страницы its.1c.ru попадёт в /WebClips/Upload/1c.ru/its/, «Прочитать позже» — в /WebClips/ReadmeLater/1c.ru/its/, а версии полного журнала — в месячных папках вида /WebClips/Backup/Journal/08-2026/WebClip_Journal_2026-08-23_18-53-10-000.json.
Постоянная ссылка сохраняется в журнале WebClip и используется для открытия файла независимо от его текущего имени и расположения на вашем Яндекс Диске. Важно: файл становится доступен любому, у кого есть эта ссылка, пока публикация не будет отключена в Яндекс Диске.

3. Фоновая резервная копия журнала

Сам журнал хранится локально. Яндекс Диск используется для версионных полных копий журнала. Предыдущие копии не перезаписываются и не удаляются; новые файлы создаются в подпапках MM-YYYY. Отдельную папку выбирать не требуется.

Значение 1440 минут соответствует 24 часам. Если очередная выгрузка была пропущена из-за закрытого Chrome, отсутствия сети или другой причины, WebClipper проверит просрочку при следующем запуске/возобновлении работы. После ошибки повтор выполняется через отдельный заданный интервал.

4. Диагностические логи операций

WebClip сохраняет подробный timeline операций локально в IndexedDB. По умолчанию логи хранятся 24 часа. OAuth-токены, Authorization, Client Secret, verification code и signed query-параметры в лог не записываются.

5. Локальное хранилище

      
Журнал, временные PDF и диагностические данные WebClip используют хранилище origin расширения. WebClip не удаляет рабочий журнал автоматически при нехватке места; перед крупными операциями выполняется проверка доступной квоты.

      
Состояние локального хранилища загружается…

      

        
        
      

      
Кнопка защиты запрашивает у Chrome режим persistent storage для origin расширения через стандартный Storage API. Новые permissions расширения не добавляются. Chrome может не удовлетворить запрос — в этом случае WebClip продолжит работать с обычной политикой хранения.

    


    

      
6. Экспорт и импорт настроек

      
Файл содержит только пользовательские настройки WebClip. OAuth access token, PKCE state, временные checkpoint'ы, журнал, состояние backup-операций и диагностические логи в него не включаются.

      

        
        
        
      

      
OAuth-секреты никогда не экспортируются и не перезаписываются импортом.
